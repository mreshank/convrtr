# Follow-ups from the monochrome foundation

Raised while executing [`2026-09-04-monochrome-foundation.md`](./2026-09-04-monochrome-foundation.md)
(Plan 1 of 4 of the [editorial overhaul](../specs/2026-09-04-convrtr-editorial-overhaul-design.md)).
Each was found by review, judged out of scope for that plan, and deliberately not fixed.
Recorded here because the plan's working notes were scratch and the findings are not.

---

## 1. The fidelity label lies about twenty tools, in both directions

**This is more serious than anything Plan 1 fixed, and it is not a design problem.**

Plan 1 corrected the *ring*: it now dashes on fidelity state rather than on a numeric
threshold, so a lossy conversion can no longer draw a stroke that says "nothing was
given up". But the ring is only as honest as the state it renders, and the state is
wrong for twenty tools.

**Eighteen understate.** They declare a preset whose id is `lossless` and whose label
the options panel shows as "Lossless", but which sets no `lossless` param — so
`fidelityState` falls through to `lossy`, `describeFidelity` returns `LOSSY`, and
`fidelityScore` returns its placeholder 50. The user is told a genuinely lossless
conversion cost them something. Affected: `jpg`/`webp`/`avif`/`heic`→`png`,
`resize-png`, `remove-exif-jpg`, `remove-metadata-png`, `jpg`/`png`→`pdf`,
`favicon-pack`, `gif-frames`, `mlw`/`avi`/`mkv`/`mov`→`mp4`, `trim-mp4`,
`frame-mp4`, `mp4-to-m4a`.

This directly contradicts the codebase's own claim — `src/core/engines/video/convert.ts`
states "A remux genuinely scores 100", and a remux scores 50.

**Two overstate.** `mkv→mp4` and `mov→mp4` give their *forced transcode* preset the id
`visually-lossless` (label "Re-encode", explanation "Decodes and re-encodes"), so the
ring draws solid on a full re-encode. Plan 1 accepted this deliberately: the mapping is
what spec §4.5 mandates for that label, and the pre-existing dash was accidental — a
placeholder score falling below a threshold that carried no meaning.

**One root cause:** preset `params` do not encode what preset `id` and `label` claim,
and `fidelityScore` falls back to 50 whenever no `quality` param exists.

**Why Plan 1 did not fix it:** the spec's non-goals bar that plan from changing
`core/quality` behaviour — it is a presentation-layer rebuild — and `describeFidelity`'s
return values were mandated byte-identical because tests assert them.

**Suggested shape:** give presets an explicit fidelity declaration rather than inferring
it from params, and replace the 50 fallback with something that cannot be mistaken for a
measurement. Both `describeFidelity` and `fidelityScore` then derive from a single
declared truth.

## 2. Guard coverage gaps

- **Nothing decodes the committed PWA icons.** `public/icons/*.png` are generated by hand
  via `node scripts/generate-icons.mjs`. The assertions only read *source* text, so
  changing the generator's constants without re-running it leaves stale binaries and a
  green CI. Verified byte-identical today (SHA-256, by re-running the generator in a
  scratch tree). A ~10-line guard — regenerate to a temp dir, compare hashes — closes it.
- **The radius sweep is asymmetric.** Borders are checked in CSS *and* Tailwind-utility
  syntax; radius only as `--radius*:` in `.css` and `borderRadius:` in `.tsx`. A
  `rounded-lg` or `rounded-[12px]` className passes untouched — and `rounded-[var(--radius)]`
  is already the codebase's idiom, so that is where drift will happen. `border-s-*`/`border-e-*`
  logical utilities and `ring-*` also fall outside the border sweep.
- **`src/app/icon.svg` is outside the colour sweep's extension list**, so the other file
  that legitimately carries literal hex is unguarded. The `manifest.ts` allowlist is
  file-scoped rather than value-scoped, so an off-palette `theme_color` would also pass.
- **The named-colour pattern requires double quotes**, so `{ color: 'red' }` escapes it.
- **No guard against declared-but-unconsumed tokens.** Several tokens and the `.meta`
  class currently have zero references — expected after Plan 1, but nothing will ever say
  so if Plan 2 fails to consume them.

## 3. Spec §4 items Plan 1 left unmet

- **§4.2's metadata voice is tokenised and never applied.** `.meta` has zero consumers;
  every metadata label still uses `.mono` plus `text-[11px] tracking-[0.08em]` with the
  uppercase baked into the string. Plan 2 inherits two competing treatments and no test
  saying which wins.
- **§4.5's "running / active: animated hairline"** is unimplemented — `ProgressBar` is a
  determinate width plus the phase readout. Defensible (a 500ms floor would misreport
  progress) but undecided on the record.
- **§4.5's "the reason stated on the adjacent line"** for `INHERENTLY LOSSY` is unmet
  beside the ring itself: `describeFidelity`'s output reaches only `aria-label`. A sighted
  user's entire fidelity signal is arc length, dash pattern and the numeral.
- **§10's reduced-motion e2e** does not exist; coverage is a text grep of `globals.css`.
  Correct to defer until reveals exist — belongs on Plan 2's list.

## 4. Traps waiting for Plan 2

- **`[data-marquee]` pauses only the element carrying the attribute.** If the marquee
  animates an *inner track* — the usual shape — the rule matches nothing useful.
  `[data-marquee], [data-marquee] *` is safer.
- **`ErrorPanel`'s inversion is the pattern `SiteFooter` will need.** It now inverts by
  redefining `--ground`/`--ink`/`--rule`/`--ink-muted` locally on the panel root, so
  descendants inherit for free. Reuse that; do not hand-override children, or the codebase
  ends up with two inversion idioms.
- **`--ink-faint` `#737373` is 4.43:1 on white** — below AA for normal text. Unused today,
  but DESIGN.md names it "secondary metadata", which is exactly what Plan 2 reaches for.
- **`--rule` at 10% as a form-control boundary** computes ~1.25:1, below WCAG 1.4.11's 3:1
  for UI component boundaries. Pre-existing, inherited from `--hairline`.
- **`BatchTable`'s dashed error edge is asserted by style but not by width class.**
  Dropping `border-l` leaves the assertions green and the signal invisible.

## 5. Cosmetic

- The comment justifying `ErrorPanel`'s removed left border calls it "visually nothing".
  On a panel whose background was `--ink`, that border was a 1px white stripe on black —
  plainly visible. Removal was right; the justification is not, on a branch that spent a
  commit removing false comments.
- `src/__tests__/deploy-config.test.ts` carries a `describe("brand mark")` block. It
  belongs beside the generator or in `src/design/__tests__`.
